# quote-search-bot

**RU** · [EN](README.en.md) · [中文](README.zh.md) · [Español](README.es.md) · [Français](README.fr.md)
[![VirusTotal](https://img.shields.io/badge/VirusTotal-0%2F75_clean-brightgreen)](https://www.virustotal.com/gui/file/e479ad7919419e88c38fe93f005203b00ea4e9e946b42b55c899c1184777773c)


Telegram-бот семантического поиска по своему корпусу текстов. Источник данных — экспорт Telegram-канала в JSON: посты превращаются в векторный индекс, поиск идёт по смыслу, а не по подстроке. Карточка результата — текст с подписью автора и картиной из пула общественного достояния (Wikimedia Commons).

Проект написан под канал цитат (философия, поэзия, афоризмы), но корпус не обязан быть цитатным: подойдёт любой канал коротких текстов — заметки, стихи, выдержки из книг.

## Возможности

- Поиск по теме («одиночество»), автору («пастернак о любви») и точной фразе в кавычках («жалость к себе»)
- Гибридный поиск: плотные векторы qwen3-embedding-4b, лексический BM25-фолбэк для редких имён и точных фраз, слияние через RRF
- LLM-разметка корпуса: kind (цитата / стих / авторское размышление), автор, источник. Правило доверия: автор проставляется только из явной подписи в тексте поста; угадывание по стилю запрещено и дополнительно проверяется кодом
- Подбор картины к карточке без LLM: тема запроса, семантическая карта «текст — картина», тема текста цитаты, стабильный хэш post_id (карточка всегда с одной и той же картиной)
- Кнопки под карточкой: ещё цитата, похожая цитата, читать полностью, Sic erat in fatis (случайная ветка)
- Справки об авторе и картине из Википедии, собираются со стримингом
- Живой ингест: бот-админ канала видит новые посты и правки, индекс пополняется на лету
- Неповторы: показанные пользователю цитаты и картины не повторяются, пока есть что показывать
- Дневной лимит 100 запросов на пользователя (админ без лимита), учёт расходов LLM в `/stats`

## Что нужно

- Python 3.12+
- Токен бота из [@BotFather](https://t.me/BotFather)
- Ключ API [bothub](https://bothub.place) — шлюз OpenAI-совместимых моделей (эмбеддинги и LLM)
- Экспорт канала: Telegram Desktop, канал, меню (⋮), Export chat history, формат Machine-readable JSON

## Запуск

1. Клонируйте репозиторий, поставьте зависимости:

   ```
   pip install -r requirements.txt
   ```

2. Скопируйте `.env.example` в `.env` и заполните `TG_BOT_TOKEN`, `ADMIN_TG_ID`, `BOTHUB_API_KEY`.

3. Положите `result.json` (экспорт канала) в корень репозитория. Проверьте парсинг:

   ```
   python -X utf8 load_corpus.py
   ```

   Напечатает число постов с текстом и первые три.

4. Разметьте корпус (один проход LLM, батчи по 15, кэш `normalization.json`; повторный прогон добирает только новые посты):

   ```
   python -X utf8 normalize.py
   ```

5. Докачайте пул картин (~900 jpg с Wikimedia Commons, вежливые паузы между запросами, занимает около часа). Шаг обязателен: без файлов карточки не отправляются.

   ```
   python -X utf8 fetch_paintings.py
   ```

6. Запустите бота:

   ```
   python -X utf8 bot.py
   ```

   При старте шьются векторы всех постов (батчи по 32, на 600 постов это несколько минут и один проход эмбеддинга) и семантическая карта картин, далее long polling: вебхук, домен и TLS не нужны.

## Обновление корпуса

- **Живой ингест.** Добавьте бота админом канала. Каждый новый пост и правка инжестятся автоматически: один эмбеддинг и один LLM-вызов разметки на пост.
- **Досинхронизация.** Команда `/resync` в чате с ботом, затем пришлите свежий `result.json` файлом. Бот дошивает недостающее — операция идемпотентна по id и тексту поста.
- **Локально, без бота.** `python -X utf8 update.py` — положите свежий `result.json` и запустите: инкрементально дошивает индекс и разметку одной командой.
- **Статистика.** `/stats` — число постов и векторов, разбивка по kind, расходы LLM за месяц.

## Docker

Картины и первичный экспорт готовятся на хосте, состояние живёт в volume:

```
python -X utf8 fetch_paintings.py
cp .env.example .env      # заполнить ключи
# result.json положить рядом с docker-compose.yml
docker compose up -d --build
```

Entrypoint перед стартом бота прогоняет разметку (идемпотентно, при актуальном кэше — мгновенно). После первичной индексизации монтирование `result.json` из `docker-compose.yml` можно убрать: обновления уходят через `/resync` прямо в volume.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `TG_BOT_TOKEN` | токен из BotFather |
| `ADMIN_TG_ID` | числовой Telegram-ID администратора: доступны `/stats`, `/resync`, приём экспорта, алерты о пропусках постов; без лимита запросов |
| `BOTHUB_API_KEY` | ключ шлюза моделей |
| `BOT_DATA` | папка состояния (индекс, разметка, SQLite, кэши). По умолчанию — папка кода; в Docker `/data` |

## Стоимость

Первичный прогон — эмбеддинги всех постов и один проход разметки; на корпусе из 600 постов это десятки центов. В рантайме каждый поиск стоит один эмбеддинг запроса, длинные запросы — ещё одну LLM-переформулировку, ингест поста — эмбеддинг плюс разметку. `/stats` показывает фактические расходы.

## Как устроено

| Файл | Роль |
|---|---|
| `bot.py` | aiogram-бот: хендлеры, карточки, колоды результатов |
| `router.py` | маршрутизация сообщения: админ-команды, интро, поиск; переформулировка длинных запросов |
| `hybrid.py` | гибридный поиск: dense + BM25, слияние RRF, политика фолбэков |
| `index.py` | векторный индекс `corpus.npz`, инкрементальная досшивка |
| `normalize.py` | LLM-разметка kind / author / source |
| `images.py` | подбор картины и кэш file_id Telegram |
| `reference.py` | справки об авторе и картине из Википедии |
| `ingest.py` | живой ингест и `/resync` |
| `store.py` | SQLite: пользователи, показанное, лимиты, события |
| `spend.py` | учёт расходов LLM |
| `cards.py` | сборка карточки: текст, автор, источник, типографика |
| `text_clean.py` | типографика показа |
| `load_corpus.py` | парсинг result.json, опциональные манифесты склеек и OCR |
| `fetch_paintings.py` | докачка пула картин с Wikimedia Commons |
| `evalset_draft.py` | заготовка эвал-сета: размечаете релевантные посты под свои запросы |
| `lab/` | замеры качества: сравнение эмбеддинг-моделей, эффект реранка |

Эмбеддинг-модель и модель разметки выбирались замером recall@5 на эталонном корпусе (см. `lab/`); обе доступны через bothub и заменяются константой `MODEL` в `embed.py` / `normalize.py`.
